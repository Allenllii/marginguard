# Sponsor bridge: diagnosis and reviewed reference boundary

The earlier HTTP-success/HOLD observations are preserved. Three distinct defects
were diagnosed in controlled synthetic development:

1. A whole-document negative phrase check treated documented conditional checkout
   restrictions as universal prohibitions.
2. A geographic qualifier check interpreted eligibility-only merchant language as
   a country restriction.
3. Nebius returned null tool metadata for an ordinary text completion. The schema
   rejected that absence of tools. Nullable metadata is now accepted; real tool
   payloads, refusals, truncated messages and changed actions still HOLD.

## Narrow, explicit review boundary

A finite sentence blacklist cannot establish arbitrary policy coherence. Real
preflight extraction readiness therefore requires the exact reviewed Shopify
source bytes: SHA-256
`21d596875d4d0f4a86db1b9e9bc0283c9ae1ce5e4de29b188b4e2e53935c51e1`.
The canonical URL remains fixed. Full-document injection, credential echo,
retraction, regional and blanket-conflict checks precede review acceptance.
Changed bytes require a new review rather than automatically updating the hash.
The eight observed conditional denial passages are not a complete policy model.
This catalog is brittle by design and supports one reference, not arbitrary URLs.

The unchanged returned excerpt remains source text. A reference permits only a
hypothetical campaign proposal. Store eligibility, exact settings, app behavior,
execution ordering and real checkout all remain unverified. In particular,
product/order stage labels in the sandbox do not emulate every Shopify rule.

Unit tests can inject an exact authored-fixture reviewer through trusted server
code. There is no HTTP field or environment variable that grants that capability.
Production Node startup and Worker construction use the strict default.

## Observed development result

One controlled real synthetic browser loop completed Search, Extract, authenticated
NVIDIA catalog verification, one completion, explicit operator confirmation and
integer-engine parity. Confirmation itself made no provider requests. This does
not authenticate a human, connect a store, demonstrate causal impact, measure
model accuracy, or permit launch. The public Site stays forced offline.

Static diagnostic codes distinguish stages without exposing upstream error text,
source bodies or secrets. Every real probe reserves a new one-shot record, stops
on failure, performs no automatic retry and preserves previous failures. Actual
request/usage observations remain in local evidence for separate release review.
No final benchmark or video was run for this follow-up.
